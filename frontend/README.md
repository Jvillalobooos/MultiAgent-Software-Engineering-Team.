## Getting Started

From the repository root, install the backend (and optionally the bundled
calculator demo project used for end-to-end smoke testing), then start the
existing FastAPI application:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[sample-app,rag,observability,dev]"
.\.venv\Scripts\python.exe -m pip install -e .\demo-projects\calculadora-qa-demo
.\.venv\Scripts\python.exe -m uvicorn sample_app.app.main:app --host 127.0.0.1 --port 8000
```

Then, in `frontend/`:

```powershell
Set-Location frontend
npm.cmd install
npm.cmd run dev
```

Vite proxies `/api` and `/ws` to that application. Runs execute in isolated
workspace copies through the repository's production LangGraph workflow.

## Verifying a run end to end

Point the project picker at a **temporary copy** of
`demo-projects/calculadora-qa-demo` (never the committed original) and send
one bounded chat message:

- The event graph rendered from `GET /api/runs/{run_id}` and
  `WebSocket /ws/runs/{run_id}` confirms the backend actually executed the
  workflow — it is not a client-side simulation.
- Diffs shown before approval reflect only the isolated workspace copy; the
  selected project on disk is untouched until Apply.
- After `POST /api/runs/{run_id}/apply`, the run card's `applied` status and
  `test_exit_code` reflect a real pytest run against the modified source
  project, confirming the source was actually changed and still passes its
  own tests.

`../tests/e2e/test_chat_apply_flow.py` automates this exact sequence
deterministically (no live LLM) against a temporary copy of the calculator
demo.
